# 📚 База образовательного контента (React SPA)

Этот мини-проект является прямым прототипом моей будущей «Базы образовательного контента». 
В рамках этой практики я создала интерфейс каталога учебных материалов с возможностью добавлять новые ресурсы, удалять их и фильтровать сразу по двум параметрам (Уровень и Формат). Все данные сохраняются в памяти браузера (`localStorage`), поэтому они не теряются при перезагрузке страницы. Также я объединила эту практику с предыдущей. 


## Ответы на теоретические вопросы (Интервью)

**1. Что такое однонаправленный поток данных в React?**
В React данные всегда передаются только в одном направлении: сверху вниз. Родительский компонент (например, `App.js`) передает данные своим дочерним компонентам (например, `ResourceList`) через `props`. Дочерние компоненты не могут напрямую изменить эти данные.

**2. Что такое «Подъем состояния» (Lifting State Up)?**
Поскольку данные текут только вниз, дочерний компонент не может сам изменить общую базу данных. Чтобы это сделать, мы применяем «подъем состояния»: родитель передает ребенку через `props` специальную функцию (коллбэк). Когда в дочернем компоненте что-то происходит (клик по кнопке "Удалить"), он вызывает эту функцию и передает данные наверх, а родитель уже сам меняет свой `state`.

**3. В чем разница между `props` и `state`?**
* **Props (свойства):** Это внешние настройки. Они передаются компоненту сверху, и сам компонент не имеет права их изменять (они только для чтения).
* **State (состояние):** Это личная, внутренняя «память» компонента. Компонент сам управляет своим стейтом с помощью хука `useState` и может его изменять.

**4. Зачем нужен атрибут `key` при выводе списков (`map`)?**
`key` (уникальный ключ, например `id`) помогает React'у понять, какие именно элементы в массиве изменились, были добавлены или удалены. Это делает перерисовку интерфейса быстрой и без багов. Без `key` React запутается при удалении карточки из середины списка.

**5. Что такое Управляемый компонент (Controlled Component)?**
Это компонент формы (например, `<input>`), значение которого жестко контролируется React-стейтом. То, что мы видим в инпуте (`value={note}`), берется напрямую из стейта, а каждое нажатие клавиши (`onChange`) сначала обновляет стейт. Инпут становится "глупым зеркалом" нашего стейта.

**6. Для чего нужен хук `useEffect`?**
Он нужен для выполнения «побочных эффектов» (side effects) — действий, которые не связаны напрямую с отрисовкой интерфейса. Например: запросы к серверу, установка таймеров или, как в моем проекте, сохранение данных в жесткий диск браузера (`localStorage`). `useEffect` выполняет эту работу аккуратно после того, как экран уже обновился.

**7. Паттерн «Компонент-обёртка» (с использованием `children`)**
Это архитектурный прием (композиция), при котором мы создаем компонент-каркас (например, `<Layout>`), который содержит общие элементы интерфейса (шапку, подвал). А всё уникальное содержимое страницы передается внутрь этого каркаса через специальный пропс `children`. Это избавляет от дублирования кода на разных страницах.
